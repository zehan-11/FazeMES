# 知识助手的文档、图谱与混合检索

入口：AI助手与知识库 → 知识助手。选择知识库范围和检索模式，输入问题后点击「检索证据」。

- 文档检索：沿用已发布文档的中文 BM25，显示片段和来源。
- 图谱检索：在当前授权图谱中匹配问题提到的实体，选择一跳或两跳关联，显示实体、关系路径和各条关系的来源。
- 混合检索：分别执行前两种检索，轮流合并候选；不把两类检索分数视为可直接比较。

例如，已发布资料分别包含「风扇 → 包含部件 → 轴承」「轴承 → 可能原因 → 润滑不足」，
输入「请问风扇的关联原因有哪些？」。一跳只到轴承，两跳可看到经轴承到润滑不足的路径。
关系按钮可打开该条来源；来源证据按钮可核对片段、文件版本和位置，并按当前权限读取原文。
箭头保留存储的关系方向，检索会同时沿入边、出边探索，路径仅表示关联，不推断因果或传递关系。

本轮只接入证据检索，不调用模型，也不创建聊天消息。文档模式保留原有发送提问功能；
图谱和混合模式暂时禁用发送提问，待后续接入基于这些证据的生成问答。

## 后端接口

POST `/admin-api/mes/assistant/evidence/search`：

```json
{"query":"请问风扇的关联原因有哪些？","knowledgeBaseIds":[],"mode":"HYBRID","hops":2,"limit":10}
```

mode 为 DOCUMENT / GRAPH / HYBRID，默认 DOCUMENT；hops 为 1 / 2，默认 2；limit 为 1..10。
兼容原 sources 参数；若同时传入 mode，二者须一致。空知识库范围表示当前可访问范围，
显式指定无权访问的库会拒绝请求，不能通过猜测知识库或实体 ID 绕过授权。

返回原 schemaVersion、query、items、hasMore，以及 mode；文档模式附 eligibleChunkCount。
涉及图谱的模式附 graph：matchedEntities、nodes、relations、paths、hops、hasMore。
matchedEntities 包含实体及匹配方式；paths 包含 rootId、nodeIds、relationIds。
每条关系仍携带统一 evidence 和独立文件来源；图谱路径中的所有关系都可点击核对。
顶层 items 只展示 limit 条候选，图谱关联预览另有上限，不能用 items 数量推断图谱总关系数。

## 匹配、边界与权限

匹配仅使用授权视图中可见的实体名称：先做 NFKC、大小写和空白归一化，再在完整问题中
寻找名称。英文名称使用单词边界；无明确提及时，仅对2至8字符短查询提供名称部分匹配，
页面会显示部分匹配说明。优先较长名称，同名不同 ID 保留各自身份。不读取原始私人别名，
也不使用模型做同义词理解或意图推断；未匹配时提示使用更具体的实体名。

先完成库授权与来源有效性校验，再定位实体和遍历，不在全库遍历后才隐藏结果。草稿、
撤回、删除、旧版本及撤权来源不能作为路径中间节点的关系支撑。来源角色撤销的下一次查询
直接生效，普通用户与管理员均沿用原有个人库/企业库权限。前端切换模式、范围、问题、
跳数或会话时清除旧结果，迟到响应不覆盖新选择。

每次最多8个种子实体、60条关系、80条简单路径；不重复走回当前路径已有节点，避免循环。
广度优先遍历，入边/出边均可走，保留原关系方向；相同关系的多个文件来源不去重丢弃。
达到上限返回 hasMore 并提示缩小范围。沿用授权快照的1万节点、5万候选关系与2万片段上限，
大规模图谱仍需后续优化索引与查询规划。

## 验证

MesGraphEvidenceRetrieverTest 覆盖完整问题匹配、1/2跳、入边方向、循环、重复来源、独立团簇、
同名实体、英文边界、容量上限及模式分发。MesKnowledgeAccessTest 验证新检索链的来源隔离与撤权。
本地运行 `python -X utf8 deploy/verify-graph-retrieval.py` 验证三种模式、多文件两跳路径、
独立/草稿排除、原文位置、版本和撤回即时过滤；仅清理本次创建的资料，不调用模型。
