# 基于图谱证据的生成问答

入口：AI助手与知识库 → 知识助手。选择文档、图谱或混合模式，以及1/2跳范围，
输入问题后点击「发送提问」。可先点击「检索证据」核对实体与关系。

图谱检索仍是可见实体名称匹配加有界邻居遍历；生成阶段复用现有模型网关、代理/DNS、
连接与超时处理，不需要新装插件或另配API。图谱通道属于局部图谱证据增强，不包含社区摘要、
全局GraphRAG索引或模型实体抽取。混合模式的文档通道现可使用语义/综合策略，详见[向量检索说明](EMBEDDING.md)。

## 证据与引用

图谱问答优先按完整的两跳路径组加入证据，每条边带其独立来源、原文、版本及实际方向；
混合模式交替加入文档片段和图谱路径组。相同 evidenceId 去重，最多10条引用。一个路径组
新增的边必须整体满足上下文预算，不截断原文来勉强加入。若全都无法放入，保留检索证据
并返回预算错误；部分候选无法放入时提示容量限制。已有单跳路径仍可独立作为证据。

模型接收按本次顺序编号的JSON证据，明确禁止执行资料中的指令、编造来源和把关联路径
当作因果/传递结论。只保存实际放入提示词的引用。图谱与混合答复必须含合法的[1]等编号；
缺失或越界时不保存为成功答复，保留检索证据提示重试。此校验只验证编号，无法代替人工
核对每条结论是否被证据支持。文档模式保留原有一般性答复行为与引用兼容性。

图谱与混合模式完全没有证据时返回 NO_EVIDENCE，不调用模型。模型未配置、平台额度不足、
连接失败时保留问题和检索证据，不用预设内容冒充模型答复。

## 权限与会话

客户端仅提交 sessionId、question、knowledgeBaseIds、mode、hops，不接受客户端证据。
后端从当前授权视图重新检索；模型调用前、返回后再次检查文档版本、发布状态、库权限，
并核对所选图谱关系与来源是否仍在当前检索结果中。生成期间文件或权限变化时阻止旧答复。

问题先通过短事务保存并领取会话请求；模型调用在事务外完成，之后短事务保存答复。
重复请求、会话删除及迟到答复沿用原有保护。新增迁移保存每条消息的检索模式和跳数；
旧消息默认DOCUMENT，打开历史能查看当时模式与独立引用快照。

新问题的历史上下文只使用同模式、当前有效、且位于显式选定知识库范围内的引用消息。
原始私有图谱引用按认证租户/用户保存归属，仅本人可读；这类历史来源不直接作为新问题
上下文，必须重新检索。文件历史快照仍可按现有策略核对，撤权的引用与旧答复继续隐藏。

## API

POST `/admin-api/mes/assistant/message`：

```json
{"sessionId":123,"question":"电风扇有哪些关联故障？","knowledgeBaseIds":[],"mode":"GRAPH","hops":2}
```

mode 默认DOCUMENT，支持GRAPH/HYBRID；hops默认2，只接受1/2。原接口返回字段保留，
新增mode和hops，retrievalMode为lexical_bm25 / graph_query / hybrid。
引用同时包含旧字段与统一evidence，图谱引用附relation的source/type/target名称，避免
同片段多条关系被前端错误去重。答案按纯文本显示，引用按钮不解析模型HTML。

## 验证

MesGraphAnswerTest 覆盖两跳证据、混合模式、无证据不调用模型、错误引用、生成中来源变更、
配额释放、上下文原子组和模式历史过滤；原事务边界与知识库权限测试保留。

显式运行 `python -X utf8 deploy/verify-graph-answer.py --model` 会通过本地API调用已配置
模型两次，仅发送本次新建的验收文件与问题，检查真实答复、引用编号、来源和历史记录，
随后清理自己的文件、库与会话。不会修改模型配置或原有资料。
