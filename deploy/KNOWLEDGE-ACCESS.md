# 个人知识库、企业规则库与统一检索证据

## 使用

AI助手与知识库 → RAG知识库中，侧栏分别列出「我的个人知识库」和「企业规则库」。
新建默认个人库，仅本人可见、可维护；具备知识库功能权限的普通用户也可以上传、
更新和删除自己的文件。具备 mes:assistant:config 的管理员可创建企业规则库，并
指定当前租户中的可读角色。角色成员只能读取已发布资料，不能修改规则或查看草稿、
历史版本；规则管理员可维护企业资料。创建者和规则管理员具有企业库读取权。

管理员的全局维护权限不覆盖个人库的所有权。知识库类型、所有者创建后不可变，
个人库不能一键改成共享库；要共享资料，明确新建企业库并上传需要共享的文件。
未选角色的企业库仅创建者、管理员可读，不默认对整个企业开放。

升级迁移 20261115_knowledge_library_acl.sql 将旧库按 creator 归为 PERSONAL、owner_id=creator，
不将任何旧资料自动公开。无法确认所有者的旧数据需人工核查，不默认转交管理员。

## 一处授权，多个入口

MesKnowledgeAccess 从认证上下文核对用户、当前/访问租户，不接收调用者指定的 ownerId。
库列表、文件列表、原文、下载、历史版本、更新、发布、删除、检索和图谱同步入口
共用库级检查；企业可读角色须属于同一租户、未删除且启用，并有当前有效的用户角色关联。
显式请求无权访问的知识库统一报不存在/无权访问；空范围仅搜索当前可访问的库。
撤销库角色授权、删除用户角色关联或停用角色，在后续检索请求中直接生效。

历史消息快照保留在数据库中用于审计。当前已失去库权限的引用不在会话响应中展示，
依赖该引用的旧助手答复显示访问受限；自己的个人库历史快照可以在文件删除后继续核对。
新问答还会排除已撤权、已删除、已撤回或版本失效的历史上下文，不把旧答案作为绕过授权的通道。

## 图谱投影与新证据有效性

Neo4j 原始实体仍可在同一存储范围内进行对齐；网页先按库权限查询当前已发布文件、
活动片段及版本，再校验每条图谱关系的文件上传者、版本、片段哈希、页码和原文位置。
没有授权来源、旧版本、已撤回、已删除和错误来源关系，不会进入可见图谱或检索证据。
该过滤不依赖后台异步删除已经完成。

原有手工初始化图谱作为 LEGACY_PRIVATE，仅原所有者可见。个人文件可与本人原图谱
匹配；企业规则按库投影实体身份，显示已授权文件的原始名称，不公开私人规范名、
别名目录、描述或原始节点 ID。不同权限域不通过私人实体对齐信息强行连接。
只由未授权关系支撑的节点也不展示。管理员维护企业规则不会因此看到其他用户个人图谱。

完整分页、实体搜索、详情与邻居均使用同一授权视图；单次服务端目录最多10000可见节点、
50000候选关系，超过即报错，不使用截断来源做授权决定。现有前端仍保留自己的渲染上限。
当前实现优先正确性，每次请求读取当前授权来源；未使用跨用户缓存。数据量扩大后需要
在保持权限与失效检查的前提下优化分页和目录查询。

## 统一证据契约

文档检索的 citation.evidence 与图谱关系的 evidence 使用同一 MesRetrievalEvidence：

- evidenceId、sourceType（DOCUMENT/GRAPH）、retrievalMethod、libraryType。
- knowledgeBaseId、documentId、documentVersion、chunkId、chunkHash。
- title、section、text、pageNumber、startOffset、endOffset、score。
- nodeIds、relationIds（文档来源时为空；手工私有来源的文档字段允许为空）。

旧引用字段保留以兼容现有界面；权限从真实库、文件和登录状态计算，不信任 evidence
中的权限描述。POST /admin-api/mes/assistant/evidence/search 可单独获取统一证据：

```json
{"query":"电机","knowledgeBaseIds":[],"sources":["DOCUMENT","GRAPH"],"limit":5}
```

默认只检索 DOCUMENT；来源同时选择时轮流合并两类候选，不宣称分数可直接比较。
文档仍是 BM25；图谱已补充完整问题中的实体名称匹配及一至两跳关系检索，网页提供
文档/图谱/混合模式，详见 [检索说明](GRAPH-RETRIEVAL.md)。三种模式已接入现有模型
生成答复，图谱证据、引用校验及调用前后检查见 [图谱问答](GRAPH-ANSWER.md)。尚未接入
向量检索、社区摘要或全局图谱索引。

## 检查

MesKnowledgeAccessTest 验证用户/管理员隔离、角色授权和撤销、图谱隐私投影、旧来源过滤、
共同证据契约和历史上下文；现有文件版本、删除同步及问答事务测试保留。
运行中的本地项目可执行 python -X utf8 deploy/verify-knowledge-access.py：创建两名临时
普通账号、两种只含知识库读取权限的临时角色、个人库与企业库，经正常 API 检查后清理。
不会调用模型、发送邮件或更改现有用户/角色授权。凭据不输出、不提交 Git。
